# Ачивки SIGame → подсказки ARG

## Рабочая схема

Ничего перехватывать из сети не нужно. Настольная SIGame уже создаёт структурированный
HTML-журнал игры. В нём есть:

- имена и индексы игроков (`data-tag="gameInfo"`);
- каждый введённый ответ (`sr n0`, `sr n1`…);
- каждое изменение счёта и игрок (`data-tag="sumChange"`).

`tools/sigame_achievements.py` читает журнал, восстанавливает счёт и статистику,
выдаёт ачивки и печатает готовые `/addhint` для Telegram-бота.

### Как использовать

1. До игры в SIGame проверь **Настройки → Оформление → «Вести логи»**. В актуальном
   клиенте настройка по умолчанию включена.
2. Проведи игру и после финального экрана **выйди из игровой комнаты**, чтобы файл
   точно был закрыт и сброшен на диск.
3. Журнал лежит в
   `%LOCALAPPDATA%\Khil-soft\SIGame\Logs\<имя>\*_log.html`.
4. Создай соответствие игровых имён Telegram-аккаунтам:

   ```powershell
   copy tools\players.example.json players.json
   notepad players.json
   ```

5. Запусти из корня проекта:

   ```powershell
   python tools\sigame_achievements.py --map players.json
   ```

   Без пути скрипт сам возьмёт самый свежий журнал. Можно указать файл/папку явно:

   ```powershell
   python tools\sigame_achievements.py "C:\path\game_log.html" --map players.json
   ```

6. Отправь напечатанные команды боту от аккаунта ведущего, например:

   ```text
   /addhint @kolya 7
   /addhint @masha 4
   ```

Полный машиночитаемый отчёт:

```powershell
python tools\sigame_achievements.py game_log.html --map players.json --json-out awards.json
```

## Набор ачивок

Ничьи не разрешаются случайным выбором: если результат одинаковый, награду получают
все лидеры. Лучше не публиковать точные условия до конца игры, иначе игроки смогут
фармить рофельные ачивки.

| Уровень | Ачивка | Условие | Подсказок |
|---|---|---|---:|
| Главная | **Чемпион** | лучший итоговый счёт | **4** |
| Сильная | **Главный мозг** | больше всего верных ответов | **3** |
| Сильная | **Снайпер** | лучшая точность, минимум 10 попыток | **2** |
| Сильная | **Банкир** | максимальная сумма всех верных ответов | **2** |
| Сильная | **Камбэк** | побывать на −1000 или ниже и закончить в плюсе | **2** |
| Рофл | **Почти 6767** | итоговый счёт ближе всех к 6767 | 1 |
| Антиачивка | **Профессор минусов** | больше всего неверных ответов | 1 |
| Рофл | **Монетка 50/50** | точность ближе всех к 50%, минимум 10 попыток | 1 |
| Рофл | **Американские горки** | минимум 5 верных и 5 неверных | 1 |
| Антиачивка | **Три страйка** | минимум 3 ошибки подряд | 1 |
| Рофл | **67-й регион** | чаще всех отправлял отдельное число `67` | 1 |
| Рофл | **Заводские настройки** | после ненулевого счёта вернуться ровно к 0 | 1 |
| Рофл | **На все деньги** | один выигрыш или проигрыш минимум 2000 | 1 |
| Рофл | **Последнее слово** | дать последний верный ответ игры | 1 |
| Антиачивка | **Лонгрид не помог** | самый длинный неверный ответ | 1 |
| Утешительная | **Долговая яма** | закончить с отрицательным счётом | 1 |
| Рофл | **Красивый номер** | итоговый счёт — палиндром минимум из 3 цифр | 1 |
| Рофл | **Идеальный баланс** | поровну верных и неверных, минимум 10 попыток | 1 |

Так сильная игровая заслуга даёт 2–4 подсказки, а любая шутка — только одну.
Одновременно рофельные награды используют разные метрики, поэтому обычно расходятся
по разным игрокам. Жёсткого лимита нет; при желании ведущий может ограничить итог,
например, максимумом в 10 подсказок на человека.

Пороговые значения вынесены в начало `tools/sigame_achievements.py`:
`MIN_ACCURACY_ATTEMPTS`, `TARGET_SCORE`, `HIGH_ROLLER_DELTA`, `COMEBACK_FLOOR`.

## Что действительно собирает SIGame

Проверено по исходникам официальных проектов Владимира Хиля:

- в конце игры сервер рассылает `GAME_STATISTICS`; на каждого игрока там идут
  `имя, число верных, число неверных, сумма выигрышей, сумма проигрышей`;
- текущие/финальные счета рассылаются сообщением `SUMS`;
- настольный клиент пишет в HTML не только итог, но тексты ответов и изменения счёта;
- SIOnline показывает ту же итоговую статистику и умеет скачать TXT-журнал;
- публичный Statistics Service не подходит для персональных ачивок: обычный отчёт
  содержит только словарь `имя → итоговый счёт`, а вопросная статистика агрегирована
  по пакету, не по конкретному игроку.

Исходники, по которым проверена схема:

- [формирование GAME_STATISTICS](https://github.com/VladimirKhil/SI/blob/8c2bee9c38d250884a3e575809172e626448a0f9/src/SICore/SICore/Clients/Game/GameController.cs#L2135-L2149);
- [структурированные теги HTML-журнала](https://github.com/VladimirKhil/SI/blob/8c2bee9c38d250884a3e575809172e626448a0f9/src/SIGame/SIGame.ViewModel/ViewModel/Logic/ViewerHumanLogic.cs#L309-L326);

## SIOnline и ограничения

Скрипт умеет читать скачанный TXT-журнал SIOnline. Из блока `GAME_STATISTICS` будут
точно получены финальный счёт, верные/неверные ответы и суммы. Но текущий SIOnline
**не записывает текст `PLAYER_ANSWER` в скачиваемый журнал**, поэтому две текстовые
ачивки — «67-й регион» и «Лонгрид не помог» — там недоступны.

Для полного набора проще всего использовать настольную SIGame как клиента ведущего
или подключить её зрителем: любой видимый клиент получает `PLAYER_ANSWER`, а его
HTML-журнал затем разбирается скриптом. Это надёжнее перехвата TCP/WebSocket и не
зависит от адреса игрового сервера.

### Известные ограничения

- При апелляциях и ручной правке счёта HTML-реконструкция может посчитать коррекцию
  как отдельное изменение. Финальный счёт останется верным, но серия ответов может
  исказиться.
- Изменение счёта на `0` нельзя однозначно классифицировать как верный или неверный
  ответ; такие события не входят в статистику скрипта.
- Если файл читается до выхода из комнаты, последние записи могут ещё находиться в
  буфере SIGame.
