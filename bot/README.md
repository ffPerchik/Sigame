# Бот квеста (трекинг прогресса)

Telegram-бот для индивидуального ARG-квеста: отслеживает прогресс каждого игрока,
сам проверяет ответы на одних стадиях и присылает тебе на апрув — на других.
QR на локациях работают через deep-ссылки на бота.

**Стек:** Python 3.10+, aiogram 3, SQLite. Квест описан в `quest/stages.yaml`.

Всё, что относится к боту и ARG, находится внутри `bot/`:

- `quest/` — сценарий, медиа, исходники и локальные отчёты по ачивкам;
- `tools/` — генераторы ассетов и анализатор журнала SIGame;
- `docs/` — пошаговая разгадка, ачивки и материалы ведущего.

## Быстрый старт

1. **Создай бота:** в Telegram открой [@BotFather](https://t.me/BotFather) → `/newbot`
   → придумай имя и username. Получи **токен**.
2. **Узнай свой user_id:** открой [@userinfobot](https://t.me/userinfobot) — он пришлёт твой id
   (это `HOST_ID`, ты будешь ведущим).
3. **Настрой окружение:**
   ```bash
   cd bot
   cp .env.example .env
   # впиши в .env: BOT_TOKEN, HOST_ID, BOT_USERNAME
   pip install -r requirements.txt
   ```
4. **Запусти:**
   ```bash
   python bot.py
   ```
   Бот напишет в консоль `Бот @... запущен`. Не закрывай, пока идёт квест (до недели).

## Как игрок начинает

В `START.txt` внутри `zengame.siq` игрок расшифровывает послание Аргуса и отдельный
ключ активации. В боте он нажимает `/start` — пролог Жени начинается сразу.
После перехвата канала Аргус ставит `ОСНОВНОЙ ПРОТОКОЛ: LOCKED` и требует тот самый
ключ из SIGame. Верный ключ автоматически открывает хаб с шестью узлами.

## Логика: где бот сам, где ты

Задаётся у каждой стадии в `quest/stages.yaml`:

| `mode` | Кто проверяет | Что делает игрок |
| --- | --- | --- |
| `info` | — | читает текст, бот сам ведёт дальше |
| `auto` | **бот сам** | присылает ответ текстом → сверяется с `accept` |
| `approve` | **ты (апрув)** | шлёт фото/файл/текст → тебе приходят кнопки ✅/❌ |
| `finish` | — | финиш |

`qr: true` — стадия-локация с QR. `accept[0]` — код в QR
(deep link `t.me/<BOT>?start=CODE`). Игрок сканит → шаг засчитан; или вводит код текстом.

### Сообщения с таймингом

В стадии можно задать общую последовательность для любых отправителей:

```yaml
messages:
  - text: "Женя: сейчас что-то произойдёт…"
    delay: 1.0
  - speaker: argus
    text: "NETWORK INTERFACE: ACTIVE"
    delay: 0.5
```

`delay` — количество секунд **до отправки именно этого сообщения**: отсчёт идёт от
предыдущего уже отправленного сообщения. После отправки скрытой дополнительной паузы
нет. `speaker: argus` добавляет реальное время и префикс ARGVS-1001; без `speaker`
отправляется обычный текст. Поле `delay` на уровне стадии таким же образом задерживает
её обычный `text` или медиа.

## QR для локаций

```bash
python make_qr.py
```
Сгенерит `qr/<stage_id>.png` для каждой стадии с `qr: true`. Распечатай и спрячь.
Пока в сценарии таких стадий нет — добавь `qr: true` и `accept: ["КОД"]`, потом снова `make_qr.py`.

## Команды ведущего (только ты)

- `/stats` — прогресс всех игроков (кто на какой стадии, кто финишировал)
- `/pending` — очередь сабмитов на апрув
- `/setstage <user_id> <stage_id>` — перевести игрока вручную (шпаргалка/спас)
- `/approve <user_id>` / `/reject <user_id> [причина]` — апрув сабмита командой (есть и кнопки)
- `/broadcast <текст>` — сообщение всем игрокам
- `/reset <user_id>` — сбросить игрока в начало

Бот сам присылает тебе уведомления: новый игрок, продвижение по стадиям, взятие подсказки, финиш.

## Команды игрока

- `/progress` — на какой он стадии
- `/hint` — подсказка (учитывается в счёте)
- `/help` — помощь

## Хостинг на неделю

- **Проще всего:** держи `python bot.py` запущенным на своём ПК/ноутбуке всё время квеста
  (через `tmux`/`screen`, или просто не выключая). Long-polling — отдельный IP/домен не нужен.
- **Если ПК выключается:** любой дешёвый VPS (Linux), `pip install`, `python bot.py` под
  `tmux`/`systemd`.
- База `quest.db` (SQLite) — рядом со скриптами. Бэкапь её, если жалко прогресс.

## Сменить квест

Отредактируй `quest/stages.yaml` и перезапусти бота. Старый прогресс в `quest.db` сохранится
(у игроков останутся их текущие стадии). Чтобы начать всем заново — удали `quest.db`.

## Связь с пакетом `zengame.siq`

Ключ из `START.txt` должен совпадать с `entry_code` в `quest/stages.yaml`.
Он проверяется не при `/start`, а Аргусом после пролога. Меняешь ключ — обнови также
`START.txt` в пакете через `../tools/build_v5.py` (`quest_start_text`).
